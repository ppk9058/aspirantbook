## 1. Audit of Legacy Baseline Claims

In previous reports (`FINAL-REPORT.md`, `RESULTS.md`), the following claims were published:
- "Legacy Docker Image Size: ~1.4 GB (unpruned dev) -> 595 MB (57% reduction)"
- "Docker Build Time: Failed during prerender -> 173.3s"
- "Legacy Memory: ~280 MB"

### Skeptical Audit Findings:
1. **Unpatched Legacy Code Cannot Build:**
   At commit `c603168`, running `docker build .` fails due to:
   - `Dockerfile:11`: `npm ci --omit=dev --ignore-scripts` stripped TypeScript and build tools required for `next build`.
   - Absence of `.dockerignore`: Copied host macOS `node_modules` (darwin-arm64) into Linux container.
   - `lib/payments/stripe.ts`: Threw `Error("STRIPE_SECRET_KEY is missing")` at module load time during page compilation.
   - `prisma/schema.prisma`: Missing Linux binary targets (`debian-openssl-3.0.x`).
   - Prerender crashes on 13 teacher and admin pages lacking dynamic directives.
2. **False Comparison (1.4 GB vs 595 MB):**
   The "1.4 GB" figure was an unpruned, dirty local development image, not an equivalent standalone production image. Comparing an unpruned dev image to a multi-stage production standalone build and claiming a "57% reduction" is scientifically invalid.
3. **Legacy Memory Claim Retracted:**
   Because unpatched legacy code never built into a functional container, the "~280 MB legacy memory" figure was unmeasured and copied from baseline runs of the current container with flags OFF.

## 2. Minimal Patch to Enable Legacy Build

To establish a truthful baseline, the minimal patch required to build `c603168` was extracted and verified at `docs/evidence/legacy-build.patch`:
- Changes: Multi-stage Debian Bookworm Slim Dockerfile, `.dockerignore`, `binaryTargets` in Prisma schema, Stripe lazy init / build placeholder, and dynamic route declarations for database-dependent pages.
