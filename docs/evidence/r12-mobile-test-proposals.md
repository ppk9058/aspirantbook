## Auth timeout root-cause hypothesis

`query-persistence.ts` itself has no interval, listener, or database open in this test path. `cache-storage.ts` selects `memoryStorageAdapter` in `beforeEach`, so its SQLite implementation is not opened. The likely open handles are TanStack Query GC timers created by `setQueryData`/`hydrate`; the third subtest deliberately retains stale data and creates an additional client without clearing it. Cleanup of every client should distinguish this hypothesis from a runner issue. This remains a hypothesis until that test-only cleanup is run; no such edit was made in R12-M.
